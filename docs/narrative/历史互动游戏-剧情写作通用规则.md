# 历史互动游戏剧情写作通用规则

版本：v1.0 · 2026-08-03
适用范围：历史、现实历史和材料考据型互动游戏，包括《佣书》和《苹果落下之前》等项目。
不包含任何项目的专有世界观、人物真相、时间线或未确认设定。

## 一、核心原则

互动剧情不是把答案藏在长文里，而是让玩家通过行动建立一条可复核、可质疑、会产生代价的证据链。

每一段内容同时维护四件事：

1. 谁在说。
2. 他凭什么知道。
3. 玩家可以做什么。
4. 这个动作会改变什么。

## 二、视角与知识来源

把句子标成以下一种来源：

- 亲见：角色当下看到的物件、动作、空间和文字。
- 亲闻：角色当下听到的对白、声音或明确传话。
- 记录：角色从账簿、档案、题签或旧文中读到的内容。
- 推断：角色把多条事实连起来后的暂定判断。
- 传言：来源可追溯但未经核实的说法。
- 设计信息：只有 UI 或规则需要呈现的提示，不能伪装成人物知识。

推断必须露出推断性。优先使用“看上去、可能、我猜、这只能说明、还缺旁证”，避免用“显然、这证明、我知道”代替证据。

## 三、场景状态表

每场戏开始前写一份最小状态表：

| 项目 | 内容 |
|---|---|
| 时间与天气 | 当前日期、光线、雨/风/潮湿等 |
| 所在空间 | 入口、出口、人物相对位置、关键物件位置 |
| 人物欲望 | 每个人此刻想得到或避免什么 |
| 已知事实 | 本场开始前玩家确实知道的内容 |
| 可见新证据 | 玩家通过读、拿、翻、听或移动才能获得的内容 |
| 不可确认项 | 本场故意保留的空缺与替代解释 |
| 选择后果 | 信任、风险、资源、关系、路线、原件状态或后续信息 |

如果一个动作在状态表里找不到前置位置、工具或结果，它就需要补写物理过程。

## 四、物理连续性

- 先交代门、桌、柜、箱、人物站位，再让物件移动。
- 每个“拿起、放下、藏起、锁进、带走、烧毁、交还”都要有可见承接。
- 不用下一句突然出现的物件解决上一句的危机。
- 空间转场要写出出入口、路程感和至少一个可复认地标。
- 角色不知道某个地点时，不能让叙事者直接跳到该地点的内部细节。

## 五、历史材料与虚构边界

项目必须维护一份断言台账，把内容分为：

- 可由原始材料直接支持的史实。
- 研究者根据材料提出的有限推断。
- 为玩法服务的职业、经济和程序设计。
- 明确虚构的人物、机构、案件、地图和交互。

写历史句子时保留来源、页码和节选边界；写游戏节译时说明“依据哪种译文转译”，不把 AI 生成的图、文字或摘要冒充原始史料。

材料线索遵守“组合比单项更有力”：纸张、墨色、页码、印记、折痕、语言和传递关系共同支持一个范围，不允许单个标记直接锁定作者或真相。

## 六、线索公平性

每个关键结论至少有两种可复查的支持方式，例如纸边 + 折痕、对白来源 + 物件位置、账簿 + 时间顺序。

玩家可以错，但不能因为作者藏掉必要信息而错。若答案已经被证据唯一确定：

- 用固定结论卡展示“目前能确定什么”和“仍不能确定什么”。
- 让玩家点击“收下判断”把它写入记录。
- 不设置三句同义选项制造虚假难度。

只有当选项代表不同的价值、风险、资源或解释路径时，才使用选择题。

## 七、玩家 agency 与不可逆后果

玩家的选择至少改变一项可观察状态：信任、政治风险、钱、纸张、路线、档案、可见信息、原件持有者或下一场的关系。

原件出售、销毁、交还和转移必须是永久状态；后续可以通过副本、引文、回忆和他人行动继续讨论它，但不能把物理原件恢复为未处置状态。

选择结果不要只在数字变量里发生。下一页要让玩家看到一个动作、一个人物反应、一个缺口或一种新的限制。

## 八、对白与自然度

- 对话先完成动作和关系，再承担背景说明。
- 每句只推进一个信息单位；长解释拆成两轮并让对方打断、回避或追问。
- 用角色职业、年龄、处境和正在做的事形成声音差异，不靠生硬口音。
- 删除只为论证而存在的排比、抽象感慨和连续否定。
- 具体写“他把钱推过门槛”“我把纸背翻过来”，少写“气氛变得神秘”。

## 九、视觉、文字与生成资产

- 图像负责材质、光线、空间和情绪；可验证的剧情文字负责事实。
- ImageGen 不承担历史原文、书名、页码、地图地名或关键线索的可读排版，除非完成逐字视觉校对。
- 生成资产要登记用途、来源、是否为表现资产，并在 UI 中叠加可靠文字。
- 纸张、地图和档案应当有材质差异，但差异服务于阅读层级，不把所有内容做成同一张复古背景。
- 动画必须让玩家知道状态变化：选中、确认、完成、失败、不可用都要有颜色、位置、形状或文字反馈。

## 十、排版与可访问性

- 句子优先在标点、语义片段和段落边界换行，避免单字孤行和常用词被硬拆。
- 关键文字不能依赖悬停；键盘、触摸和指针应能完成同一核心操作。
- 小字、地图注释和证据卡不能依赖内部滚动才能读完。
- 颜色变化必须配合文字、形状或位置变化；不能只用颜色表达成功/失败。
- 减少动态偏好时保留信息顺序和确认结果。

## 十一、交稿检查表

### 叙事

- [ ] 每个全知句都能回溯到人物知识来源。
- [ ] 每个关键结论都列出仍然缺少的旁证。
- [ ] 人物年龄、职业、地理和时代语言一致。
- [ ] 每个场景至少有一个推进/阻碍欲望的动作。
- [ ] 没有重复上一页已经解决的线索。

### 交互

- [ ] 每个交互回答一个叙事问题。
- [ ] 选择题代表真正不同的后果或解释。
- [ ] 固定答案使用证据结论卡，不使用假选择。
- [ ] 处置原件后不可逆状态被保存并在后续可见。

### 视觉与工程

- [ ] 生成图没有承担未经校对的史料文字。
- [ ] 关键状态有明确视觉与文本反馈。
- [ ] 桌面、窄屏、键盘和 reduced-motion 路径均检查。
- [ ] JSON、类型、档案、研究台账和 UI 文案相互一致。

## 十二、复核流程

1. 叙事组检查视角、人物、事实边界和线索公平性。
2. 游戏设计组检查交互是否必要、是否有 agency 和可观察后果。
3. 技术组检查 JSON graph、类型、资源路径和不可逆状态。
4. 视觉组检查层级、材质差异、可读性和点击反馈。
5. QA 运行测试、lint、build，并检查桌面/窄屏/键盘。
6. 独立复读者不依赖上一轮结论重新列出通过项、失败项和待设备确认项。

没有证据的“完成”只能写成“待复核”。
