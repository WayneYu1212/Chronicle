# 《佣书》剧情写作规则

版本：v1.0 · 2026-08-03
适用范围：`C:\Users\UUWayne\Desktop\Chronicle` 的剧情、人物档案、史料长编、交互文案与相关验收。

这份规则是《佣书》的项目约束，不是明代广州通史。凡是历史事实、游戏推断和虚构设定，必须在写作时分层。

## 一、不可越过的项目基线

1. 故事当前时间是康熙九年（1670）；主角约二十三岁，约生于 1647 年，对 1650 年广州城陷没有可靠亲历记忆。
2. 主角是佣书，先做分类、誊抄、修补、查验，再作判断。不能一开口就知道作者、原稿、传播链和政治动机。
3. 第一章保留三个问题：谁写了残页、沈掌柜为何认得它、还有谁在找。第一章只建立证据和压力，不一次回答全部问题。
4. 沈掌柜的主要显示名永远是“沈掌柜”。“沈子壮”只作为虚构人物档案中的姓名线索和时代命名启发，不借用陈子壮的历史身份。
5. 小满约十六岁，出生晚于 1650 年；他可以熟悉当下的城门、巷路、天气和书坊杂务，不能拥有庚寅之劫的亲历记忆。
6. 原件一旦出售、销毁、交还或转移，后续只能出现副本、引文、记忆和影响，不能让原件魔法般回到手里。
7. 故事事实只写入 `src/story/*.json`；React 组件负责呈现和交互，不在 JSX 中硬编码新的剧情事实。

## 二、史实、推断与虚构分层

| 层级 | 写法 | 例子 |
|---|---|---|
| H1 | 可由可靠史料直接支持 | PDF 译文中“当整个城市更像一座坟墓……” |
| H2 | 有来源，但需要说明推理链 | 报告经澳门传播、后来出现编抄层 |
| H3 | 为职业体验或玩法服务的合理推断 | 佣书按书坊内部规则记账 |
| H4 | 明确虚构的角色、机构、案件和材料 | 听雨书坊、沈掌柜、小满、访客网络 |

写入游戏前，每条会被玩家当作现实知识理解的内容都要登记到 `docs/research/CLAIMS.md`。H3/H4 可以好用，但不能伪装成 H1。

## 三、主角视角规则

每个旁白句子先回答：“主角现在凭什么知道？”来源只允许是：

- 亲眼看见的纸、墨、折痕、针孔、脚印、物件位置和动作。
- 当场听见的对白或后来明确转述的消息。
- 从多个事实得出的有限推测，必须用“看上去、像是、我猜、或许、只能说明”标记。
- 玩家的手札判断；判断可以错，但不能改写已经见过的事实。

禁用没有来源的全知表达：

- “这说明所有经手人都……”
- “他显然知道全部……”
- “我知道这一定是……”
- 只为论证服务的“没有……也没有……”
- 把后来的历史答案塞进当下人物的脑中。

## 四、人物写作

### 主角

- 句子短，先报纸墨与动作，再作判断。
- 可以担心钱、饭、店规和连累雇主；不要用现代研究术语展示聪明。
- 每次越过店规、隐藏碎片或处理原件，都要留下现实代价。

### 沈掌柜

- 主要剧情、对白、说话人标签统一用“沈掌柜”。
- 熟悉部分材料和流转关系，但不能成为百科全书；常用规则、动作和反问让主角自己分层。
- 对敏感材料的保护必须通过锁、账簿、封套、题签、路线和交代体现。
- 他知道的事情必须有来源：亲手经办、旧账记录、旧友转述或多年交易网络。

### 小满

- 关注饭钱、雨势、门路、脚夫和书坊具体活计。
- 每场最多使用一个经过研究的广州地方词；地方感来自观察，不靠连续方言字。
- 他可以提出尖锐问题，但不能直接给出历史真相。

### 陌生客人

- 年龄、雇主和身份保持开放；准确说出的每一处残页特征都要有信息来源。
- 说交易式短句，给钱、留物、试探和退出比反派宣言更有效。
- 不用“神秘”替代行动，不让他无理由知道玩家尚未见过的内容。

## 五、材料与物理证据

写一份纸时至少记录：纸幅、纸料、折法、边缘、墨色、书写层次、后添标记、发现位置和当前持有者。

白棉纸可以是较好的纸料，竹纸可以是普通旧纸；任何单项都不能自动证明年代、作者或路径。有效线索通常是组合：

> 窄幅 + 密集横折 + 纸背墨层 + 后添页码 + 蜡屑/针孔/蓝线

但组合也只支持“存在转抄或流转迹象”，不能直接跳成“找到原稿”。

写空间时用可复述的位置关系：门槛、柜台、门内小几、茶盏、后院窄门、箱子、青砖和水缸。任何拿、放、锁、搬、翻和离开的动作都要能在这个空间里发生。

## 六、P29/P40 的验收写法

### P29 残页

- P29 是一张残页，先显示可观察事实，再让玩家收下判断。
- 董少新译注中的历史句子要保留来源边界；省略号表示节选，不补写未见内容。
- 纸背日期是后出旁注，不得替正文确定日期。
- ImageGen 只生成纸面材质、潮痕、折痕和蜡屑。可靠汉文、葡文、页码和热点由 DOM/JSON 排版。
- 纸背文字必须正常阅读方向，禁止水平镜像。

### P40 封套与碎纸

- P40 的三片碎纸来自第二箱青砖下的旧封套夹层，不是 P29 原页重复出现。
- 比较交互若只有一个可由证据推出的结论，不设置假选择题，直接展示结论并提供“收下判断”。
- 三片碎纸可以保留拼合，但必须让折线、针孔、纸边和背面墨线共同发挥作用。
- 新的葡文必须标注为依据中文译文转译的游戏节译；不能声称发现了原始葡文底本。

## 七、对白与金钱

- 对话优先用“就、先、再、别、还没”，少用“便、遂、尔后”等书面连接词。
- 一句对白只承担一个动作或一个判断；需要解释时拆成两轮。
- “没有……也没有……”只有在并列事实本身重要时使用；若只是强调论点，改写成正面动作。
- 听雨坊的工钱是 H3/H4 游戏经济。当前第一日分类、跑腿和杂役共记六文，访客十五文添价，不能写成广州佣书行业统计。
- 任何价格变化要影响饭钱、风险、信任或原件处置，而不是只作漂亮数字。

## 八、交互与手札

- 交互必须回答一个叙事问题：它让玩家看见什么、确认什么、承担什么或失去什么。
- 只有一个正确答案且证据已足够时，使用固定结论 + “收下判断”，不要让玩家在三句同义选项中猜答案。
- 有意义的选择必须改变信任、风险、保存方式、路线、可见信息或后续关系。
- 手札按最近出现的条目置顶；所见、判断、疑问、待查和线索分开显示。
- 玩家的判断可以保留低可信度，不能覆盖原件已经产生的永久处置记录。

## 九、每场戏交稿前检查

1. 主角此刻看见、听见还是推断？
2. 每件物品在场景中的位置是否明确？
3. 人物年龄、地点和知识边界是否成立？
4. 是否有一个动作推进或阻碍当前欲望？
5. 是否把 H3/H4 写成了 H1？
6. 是否重复了上一页已经完成的检查？
7. 是否出现单字孤行、词组硬拆或需要内部滚动的小字？
8. 选择题是否真的产生分歧？若没有，改成固定证据结论。
9. 原件处置后是否仍遵守不可逆规则？
10. `src/story/*.json`、档案、CLAIMS 与 UI 文案是否一致？

## 十、验收门槛

每次改剧情后至少运行：

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

另需检查桌面、390px 左右视口、全键盘、纸背方向、地图点击态和 ImageGen 资源实际加载。未完成的真实设备检查必须在交付报告中单列，不能用“本地通过”代替。
