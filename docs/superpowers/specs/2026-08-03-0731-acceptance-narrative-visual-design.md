# 0731 验收修订与剧情规则沉淀设计规格

## 目标

根据 `0731验收.txt` 修订《佣书》当前可玩章节，使叙事视角、物理空间、证据链、玩家判断、文字排版与视觉层次达到可验收状态；同时把本次修订抽象成一份《佣书》专用规则和一份可复用于《苹果落下之前》的历史互动游戏剧情规则。

## Studio 归属与决策边界

- 主责组：叙事与研究组。
- 主责导演：Narrative Director。
- 协作审查：Game Director、Art Director、Technical Director、QA Director、Production/Documentation Director。
- 独立复核：Independent Review Director；当前工作区没有第二个独立线程，采用完成后的新鲜复读审查，并明确标注独立性限制。
- 级别：L3。涉及章节内容、交互行为、视觉资产、公共排版规则与项目文档。
- 创始人决策：本规格已获用户批准后进入实现；影响故事真相、人物命名和跨项目规则的争议仍由用户最终裁决。

## 范围

### 包含

1. `src/story/*.json` 中与 0731 验收相关的第一章、第二章内容和交互数据。
2. 残页检查、P40 证据比较、碎纸拼合、地图路线确认等现有交互的最小必要改造。
3. 听雨书坊的空间连续性、陌生客人信息来源、沈掌柜与小满的档案信息、手札倒叙显示。
4. 中文词组换行、开屏光线、地图反馈、残页材质图等视觉与可读性修正。
5. 两份 Markdown 剧情写作 rules。
6. 与新史料用法直接相关的研究断言和验收记录。

### 不包含

- 不修改《苹果落下之前》的任何代码、剧情或资源；只提供可复用规则文档。
- 不把沈掌柜改写成历史人物；“沈子壮”只借用明末广州府科举人物的命名气息，历史身份仍为虚构。
- 不把白棉纸、页码或葡文单项写成“看到就能锁定来源”的唯一证据。
- 不提前回答第一章必须保留的三个问题：残页由谁写、沈掌柜为何认识、还有谁在找。
- 不提交、不推送、不覆盖工作树中与本任务无关的用户修改。
- 不以浏览器截图代替真实设备触摸与字体验证；未完成的设备验证会保留为风险。

## 叙事设计

### P29：残页作为一张可检验的物证

残页正文采用验收指定的历史句子：

> 当整个城市更像一座坟墓，死的人比活的人还多之后，弯刀停下来了。

实现前须在董少新《曾德昭〈鞑靼人攻陷广州城记〉译注并序》中复核句子位置和上下文。界面将其作为译注材料中的节选，不宣称是曾德昭亲笔原稿。

玩家先看到可观察事实，再得到有限判断：

- 白棉纸、窄幅、密集横折：可见的纸张与使用痕迹。
- 正面青灰汉文、纸背淡墨西文/葡文层：可见的双层书写。
- 右上角后添的“十三”：页码线索，不等于书名。
- 横折深处暗红蜡屑：可能与封存、转递或装订有关，但不能单独确定经手人。
- 斜光下墨迹避让：只描述“后写层避开底层墨迹”的物理现象；不再直接说“不能当作现场写成的原稿”。

生成图只负责纸张材质、折痕、边缘、墨迹渗化和蜡屑氛围。可读正文由 React/HTML 叠加，纸背使用正常阅读方向，禁止 `scaleX(-1)` 或任何水平镜像。

### P40：从残页转向转抄/封套证据

第二箱场景必须按空间顺序交代：

1. 第一箱清完后，沈掌柜让主角先吃饭，第二箱暂时不动。
2. 第二箱位于后院靠墙处，青砖压在旧书册上方，砖下是可见的旧封套。
3. 封套夹层中取出三片手掌宽碎纸；它们不是 P29 残页本身，而是同一批材料的旁证。
4. 通过纸边、折线、针孔、背面墨线和汉文节译的层次，判断这些碎片曾被编入另一份材料。

“比较”交互不再让玩家在唯一正确答案中猜选项，而是呈现一次可复核结论，并由玩家点击“收下判断”。结论的措辞保持证据等级：可以说“夹层碎片与残页存在同一批转抄材料的迹象”，不能说“已经找到原稿”或“已经确定全部经手人”。

碎纸拼合保留为一次有意义的物理核对：玩家需要依据折痕、针孔、纸边和背面墨线把三片放回顺序；不使用当前重复 `Padre` 词的低信息文案。拼合完成后显示一条新的葡文节译，并在界面注明它是依据 PDF 中文译文转译的节选，而非声称保存了原始葡文底本。

### 访客场景

- 开场先定义门槛、柜台、门内小几、茶盏、后院和箱子的相对位置。
- 残句接上后，门环声写成主角听到的节奏和力度，不使用全知式“仿佛知道店里的人一定会开门”。
- 陌生客人直接说出复合特征：窄幅白棉纸、密集横折、页角后添的“十三”、纸背另有西文墨迹；这些信息必须能从买家、中间人或委托人处解释，而不是凭空知道。
- “真正令我不安”的内容改成具体观察，不把白棉纸单独写成罕见标记。
- 陌生客人离开时，铜钱位于门槛内外关系明确；沈掌柜蹲下拾取，并从门内小几拿空茶盏收好，再锁进柜中。
- 询问改为“若有人问掌柜在不在”，不再出现未铺垫的“问店里几个人”。
- 日工钱与残页交易价下调为克制的游戏内虚构数值，并在规则中注明不能当作明代工资统计。

## 人物与视角

- 主角约二十三岁，不能拥有 1650 年广州城陷的可靠亲历记忆；句子保持短、先观察再判断。
- 沈掌柜的主要剧情显示名统一为“沈掌柜”；档案补充姓名“沈子壮”，并标记为虚构人物的命名启发。
- 小满约十六岁，补入右侧手札的人物档案；语言具体、活泼，每场最多使用一个经过研究的广州地方词。
- 所有“说明”“证明”“意味着”类句子都要检查叙事者是否拥有该知识；无法确定时改为“我猜”“看上去”“或许”“这只能说明……”。
- 角色动作必须能推进或阻碍当前欲望，避免用抽象感慨替代行动。

## 视觉与交互设计

### 开屏

把当前单一的棕色网格替换为低饱和暖纸色光线射束：射线从书页/门缝方向散出，边缘有柔和散光，中心亮度受控，保持古籍与雨天的压低气质，不引入外部视觉依赖。

### 中文排版

对 `SentenceText` 增加语义片段级换行策略，优先在标点、短语边界和显式段落处换行，避免单个汉字孤立成行，也避免常用词组被硬拆。移动端仍需允许极长专名在必要时降级断行。

### 地图

- 删除“山川依旧 · 文字后添”这一抽象比例注释。
- 地图卡正文完整展示，减少小字、固定高度和内部滚动。
- 路线点击后，按钮改变颜色、轻微倾斜并短暂显示“已选定”；选中地点同步强化状态。

### 残页 ImageGen 资产

- 生成目标：一张横折密集、边缘略旧、带青灰墨迹和暗红蜡屑的窄幅白棉纸残页。
- 生成限制：不生成可依赖的可读汉字、葡文或页码；不生成现代装订物、现代桌面、塑料、打印字体和镜面文字。
- 使用方式：图片作为材质/底图，真实文字、热点和纸背内容由界面叠加；生成图保留在 `public/assets/`，并通过静态资源引用。
- 验收方式：生成后用图像查看工具复核纸张方向、折痕和蜡屑，再进行桌面与移动端浏览器检查。

## 验收与证据

实现完成后按以下顺序验证：

1. JSON 解析、故事结构和现有单元测试。
2. 针对 P29/P40/访客/地图/手札/换行的回归测试。
3. `npm.cmd run lint`、`npm.cmd test`、`npm.cmd run build`。
4. 桌面浏览器、390px 左右移动视口、键盘操作与地图点击状态。
5. ImageGen 资产实际加载、纸背方向、无镜像检查。
6. 叙事导演审查、技术/视觉/质量审查、独立复读审查。
7. 所有证据通过后，再更新 Chronicle Obsidian 的 README、decisions、log 与 TODO；若设备或环境验证未完成，明确保留为风险。

## 完成定义

只有同时满足以下条件才可称为完成：

- `0731验收.txt` 中的文本、视角、空间、交互、地图、视觉和经济问题均有对应改动或有证据说明无需改动。
- 两份 rules 已写入并与实际实现一致。
- 残页图片已生成、插入并通过方向与加载检查。
- 测试、lint、生产构建均有本轮新鲜输出。
- Studio 复核报告列出通过项、剩余风险和独立性限制。
- 没有修改《苹果落下之前》的项目文件，没有提交或推送。
