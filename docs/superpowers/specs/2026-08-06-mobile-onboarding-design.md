# 移动端新手引导与阅读界面设计

## 目标

让第一次打开《佣书》的玩家在不阅读长说明的情况下理解：当前页是剧情阅读区，手札记录即时观察，长编整理史料；同时修复手机端页面高度、底部导航和长内容导致的显示错乱。

本次只修改界面引导、阅读层级和响应式布局，不修改 `src/story/*.json`、存档字段或史料判断规则。

## 已确认的教程文案约束

- 每条教程标题和说明均不超过 30 个字符。
- 必须明确说明手札用途：记录所见、疑问和线索。
- 必须明确说明长编用途：整理材料，填写来源和判断。
- 教程首次进入游戏自动出现；完成后不重复打断阅读。
- 游戏内保留一个紧凑的“？”帮助入口，玩家可随时重看。

拟定四步文案：

| 步骤 | 标题 | 说明 |
| --- | --- | --- |
| 1 | 先看正文，再做选择 | 人物名在左，“旁白”记录你的所见。 |
| 2 | 手札：记下所见所疑 | 手札记录观察、疑问和线索。 |
| 3 | 长编：整理史料判断 | 长编整理材料，填写来源和判断。 |
| 4 | 点页翻读，底栏导航 | 点正文翻页；底栏可打开其他页面。 |

文案通过 `Array.from(text).length <= 30` 做静态回归检查，避免后续改写变成长说明。

## 交互结构

### 教程状态

新增独立的教程步骤数据与本地状态工具。状态键使用版本化名称 `chronicle-tutorial-v1`，只保存是否完成，不进入游戏存档，因此不会影响旧存档迁移、重置和跨章节数据。

- `/game` 首次加载并完成书页初始化后，教程覆盖层出现。
- 新游戏的卷首动画先完成，再显示教程，避免教程盖住开书动画。
- 继续游戏同样显示一次；已经完成教程的玩家不被再次打断。
- 点击帮助入口时直接打开教程，不修改完成状态；点击“知道了”或完成最后一步时标记完成。
- 帮助入口在桌面和手机都可见，但不增加底部功能栏项目，避免手机窄屏出现按钮拥挤或换行。

### 教程覆盖层

使用一个无外部依赖的 React 组件：

- `role="dialog"`、`aria-modal="true"`，标题与当前步骤关联。
- 提供上一步、下一步、关闭和完成动作；按钮最小触控尺寸为 44px。
- 当前步骤显示 `1 / 4`，每次只展示一条短说明。
- 关闭后恢复帮助按钮焦点；打开时把焦点放到标题或关闭按钮。
- 手机端使用 `max-height: calc(100dvh - 32px)` 与内部滚动，内容不依赖固定屏高；覆盖层不产生横向滚动。

### 阅读层级

在不改剧情内容的前提下增强现有页面语义：

- 旁白标签明确显示“旁白”，不再只依赖容易被误认为手札的“记”。
- 人物对话继续显示说话者姓名，并保留当前纸页视觉风格。
- 教程用短标签解释“当前正文”和“手札/长编”的关系，帮助移动端玩家建立页面心智模型。
- 移动端继续采用单页阅读；“手札”按钮打开左页内容，手札内部的“手札 / 长编”标签保持原有切换。

## 手机端布局修复

只在现有响应式断点内做针对性修复：

- 书页高度改用支持动态地址栏的 `dvh`，并保留 `svh`/现有降级，减少 Safari 地址栏伸缩造成的裁切。
- 书页内容区允许纵向滚动，禁止横向溢出；长段、活动卡和长编表单使用 `min-width: 0`。
- 底部导航在安全区内布局，按钮不强制挤压文本；帮助入口放在书页顶部的紧凑控制区。
- 教程、手札抽屉、课簿和活动内容都使用 `box-sizing: border-box` 与可缩放宽度，避免出现截图中的页面突然变大。
- 390px 左右窄屏、横屏和桌面双页均保持可读；不改变已确认的纸张、字体回退链和地图视觉方向。

## 文件边界

预计修改：

- `src/lib/tutorial.ts`：教程步骤、版本化状态键和安全的浏览器状态读写。
- `src/lib/tutorial.test.ts`：文案长度、步骤内容和状态工具测试。
- `src/components/TutorialOverlay.tsx`：覆盖层、步骤切换和可访问操作。
- `src/components/BookShell.tsx`：帮助入口和教程触发接口。
- `src/app/game/page.tsx`：教程显示时机和完成状态接入。
- `src/components/ManuscriptPage.tsx`：旁白语义标签。
- `src/app/globals.css`：教程样式、动态视口高度和移动端溢出保护。

不修改：

- `src/story/*.json`；
- `src/types/game.ts`、存档 schema 和迁移；
- `src/components/ActivityStage.tsx` 的史料玩法；
- 与本任务无关的工作树用户改动、`.next` 和其他构建产物。

## 验收标准

1. 全新浏览器进入 `/game?mode=new`，卷首动画后自动出现教程；教程每条文案长度不超过 30 个字符。
2. 教程明确说明正文、旁白、手札和长编的区别；完成教程后刷新不再自动出现。
3. 点击帮助入口可重看教程；关闭后可以继续翻页，焦点返回帮助入口。
4. 手机宽度约 390px 时无横向滚动；正文、手札、长编、活动卡和底部导航都不裁切，长内容只在对应区域纵向滚动。
5. 手机端可以打开“手札”，并在“手札 / 长编”之间切换；桌面双页行为保持不变。
6. 现有自动化测试、lint、TypeScript 检查和生产构建通过。
7. 使用浏览器检查桌面、390px 竖屏、390px 横屏和至少一个窄屏地址栏状态；真机检查仍单独记录，不以自动化替代。

## 风险与取舍

- 教程使用浏览器本地状态，清除站点数据后会再次出现，这是预期行为。
- 不把教程写进剧情 JSON，避免教程复制到历史叙事、改变章节图或影响存档。
- 不新增底部导航项，牺牲一个显眼的独立“教程”文字按钮，换取手机端导航不拥挤；顶部“？”入口承担重看功能。
