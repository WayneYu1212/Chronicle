# 《佣书》第六至第十章研究与批准规格

状态：创始人批准前草案；只固定 PRD 已批准的“转—合”职责与实施门，不批准具体正文、章名或结局阈值。
日期：2026-08-12
主责：游戏设计组；叙事与研究、技术工程、QA、制作文档会签

## 目的与边界

仓库目前没有第六至第十章正文或扩写包。第五章只留下 `burial-register-loan-note` 和“第六章《瘗簿》”这一安全种子。依照 L3 规则，本规格先把研究问题、章节职责、数据契约、验收和创始人决策列清；在批准前不创建 `chapter06—10.json`，也不把 `YS-P4-01` 或 `YS-P5-01` 勾选完成。

## 三种推进方式

### A. 资格分层而非失败门（推荐）

第九章检查来源链、来源角色、事件覆盖、可复核程度、矛盾与缺失。材料不足的玩家仍可完成“受限稿”，但正文更短、附录和留白更多，并明确哪些句子无法写。第十章不评唯一满分，只让材料结构改变正文、附录、存疑、留白和风险。

优点：符合“完成书写不等于唯一真相”，不可逆处置不会把玩家锁死；资格规则可解释。代价：需要较完整的结构化来源和写作状态。

### B. 硬阈值准入

满足固定独立来源数、角色数和事件覆盖数才进入第十章，否则必须回查。优点是目标明确；缺点是容易把历史研究变成收集清单，也可能惩罚早期有意义的永久处置。

### C. 隐藏评分

把来源质量、数量、矛盾和风险合成分数，自动选择结局。实现最省界面解释，但玩家难以理解结果为何变化，也违背项目对可复核判断的要求，不推荐。

## 推荐的十章后半结构

工作章名仅用于讨论，不进入正式 JSON。

### 第六章：瘗簿（工作名）

叙事职责：从第五章“借记”追到原簿、旧抄、姓名残片或明确失去；让玩家第一次以“姓名与埋葬行动”而非总数处理死亡记录。

研究门：清初广州城南地理、埋葬/义冢/善后记录、姓名簿与家户记录形制。若无法从 S1/S2 定位，义冢、香火箱、守冢人和瘗簿制度保持 H4；不得用一册簿推出全城死亡总数。

玩法门：借记查验、保管链核对、异名归并、残缺名单和空格著录。永久结果至少包含原簿可复验、仅有可靠副本、仅有摘记、失去访问四类。

章节出口：形成一组“可确认姓名/仅姓/无法辨认/地点不确定”的结构化记录，并把一项访问或保管损失带入第七章。

### 第七章：两种记录者（工作职责）

叙事职责：让同一事件出现亲见、家族转述、机构记录与后出编纂的冲突；揭示记录者为何删、为何沉默、为何只写一部分。

研究门：口述史方法只作现代幕后方法，不伪装成清初术语；人物年龄、地点、关系、说话时间逐项审校。真实制度或人物一旦进入正文，重新登记 H1/H2。

玩法门：证词关系图、可见范围、版本校记、同意范围与二次访问。玩家不能同时获得所有材料：公开姓名、保护口述者、取得官署副本和维持私人访问之间至少存在一次不可兼得。

章节出口：保存冲突而非消灭冲突；至少一项沉默、撤回、删名或拒绝复制成为永久缺失。

### 第八章：覆盖冻结

叙事职责：结束无限追索。玩家必须冻结自己能够书写的事件范围和来源类别，明确哪些问题进入第九章、哪些留白。

研究门：列出全部玩家可见 H1/H2 断言和 H3/H4 案件命题，确认没有把同源转抄当独立来源。

玩法门：事件覆盖板、来源角色板、依赖链去重、材料保管审计和“冻结/继续存疑”决定。冻结后仍能更正勘误，但不能靠普通操作复活已失原件或无限新增远程线索。

章节出口必须写入：事件覆盖集合、来源角色集合、独立来源链、关键矛盾、永久缺失、仍可复核材料和玩家明确放弃追索的项目。

### 第九章：书写资格

叙事职责：检查玩家是否拥有一套可诚实书写的材料结构，而不是数够收藏品。

推荐资格项：

- 至少覆盖“事件经过、具体人物/地点、材料形成与传播”三种问题中的两种；未覆盖项必须进入留白。
- 至少两条彼此独立的来源链；同一原件的译抄、摹本和摘要只算一链。
- 至少两种来源角色，例如机构档案、直接见证/有限亲见、同时代或代际转述、他人书写、物质传播记录。
- 至少一条矛盾被结构化保留，至少一项永久缺失被明确著录。
- 每个拟入正文的命题都有来源链、支持范围和反证/缺失说明。

这些数值是推荐默认，不是已批准阈值。创始人可选择“受限稿仍可进入第十章”或“必须回查后准入”。

### 第十章：完成长编

叙事职责：把玩家已有材料写成正文、附录、存疑和留白；结束于承担一版书写，而不是获得唯一真相。

玩法门：逐命题选择位置、措辞强度、姓名处理、引文范围和版本校记；每一段显示来源链、依赖副本和永久缺失。系统允许修订，但保留版本差异和谁提出了修改。

结局变化：正文长度与确定程度、附录结构、存疑条数、留白主题、公开风险、相关人物可访问性和后续勘误入口。禁止单一真相值、隐藏道德分或“全收集=真结局”。

## 实施前必须补的数据契约

当前 `SourceFragment` 只有 `sourcePerson`、`transmission` 和 `relatedEvents`，不足以判断独立性；第五章专业活动又只把选择压入字符串 `clues`。第六章正文实施前，应先提出存档 v2 迁移并至少加入：

```ts
type SourceRole =
  | "institutional-record"
  | "direct-witness"
  | "contemporary-retelling"
  | "intergenerational-retelling"
  | "later-memory"
  | "other-writing"
  | "material-transmission";

interface ProvenanceRecord {
  sourceChainId: string;
  derivedFrom?: string[];
  sourceRole: SourceRole;
  eventCoverage: string[];
  claimIds: string[];
  access: "open" | "restricted" | "closed" | "lost";
  copyPermission: "none" | "limited" | "full";
  custody: string;
}

interface WritingDecision {
  claimId: string;
  placement: "main" | "appendix" | "doubtful" | "omission";
  wordingStrength: "states" | "reports" | "suggests" | "unknown";
  sourceChainIds: string[];
  missingEvidence: string[];
  version: number;
}
```

兼容要求：旧存档中的 fragments/entries/clues 先迁移为“来源链未分类”，不得猜测独立性；第五章已完成但缺少结构化选择时，进入第六章前显示一次可解释的补录流程，不静默生成玩家未选过的访问或删名决定。

5. 第十章是否允许玩家完成内容很少但来源诚实的“受限稿”，而不设置失败结局？
6. 是否批准存档 v2 和第五章选择补录流程？

## 验收与独立审查

- 每章遵循研究简报→获批规格→实现→叙事 QA→历史审校→浏览器验收。
- 第八章测试能去重同源派生材料，并冻结事件覆盖/来源角色/缺失。
- 第九章资格对同一原件的原件、抄本、译抄和摘要只计一条来源链。
- 第十章每种材料结构都能形成正文/附录/存疑/留白差异，没有失效跳转或唯一真相值。
- 旧存档迁移、拒绝补录、损坏数据和未来版本安全失败均有测试。
- 自动化、浏览器、真机、历史审校、5 名目标玩家与创始人批准分别记录。

## 规格自审

- 没有创建未获批正文或故事 JSON。
- 所有工作章名和数值阈值均标为待创始人决定。
- 数据模型解决现有独立来源、权限与动态写作缺口，没有提前引入后端或联网系统。
- 早期不可逆处置不会直接造成死档；它改变资格、措辞、留白和可复核性。
