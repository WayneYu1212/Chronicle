## 信任与使用层级

| 层级 | 资料 | 用途 | 可否单独支持 H1/H2 |
|---|---|---|---|
| S1 | 原始文献、影印本、方志、年谱、档案汇编 | 核对原文、版本、年代与同时代叙述 | 可以，但争议事实应交叉核对 |
| S2 | 正式出版专著、学位论文、学术论文 | 研究史、解释、争议与书目追踪 | 可以，记录页码与作者观点 |
| S3 | 用户自己的论文、笔记和整理 | 发现论点、已有引用和研究路径 | 需回查其引用的 S1/S2 |
| S4 | MinerU/OCR 转写 | 全文搜索和段落定位 | 不可；必须核对原 PDF／版本 |
| S5 | AI产出、聊天摘要、写作模板、旧草稿 | 生成检索词和发现可能线索 | 不可 |

## 按需检索流程

1. 从一个具体游戏断言或章节问题开始，不以“读完整个库”为任务。
2. 先搜索文件名，再用 `rg` 搜索 Markdown 和文本；繁简体、异体字、年号与公历词并用。
3. 从命中结果选择 1—3 个最相关来源，只读取相关章节或页面。
4. 若命中 OCR／Markdown，打开对应 PDF 核对原文、页码、脚注和版式。
5. 把采用的证据写入 `CLAIMS.md`：书目信息、母库相对路径、页码、H1—H4 分类、支持范围、争议和审校状态。
6. 对核心事件、数字、日期、人物行为和存在争议的解释，尽量使用不同来源链交叉核对。
7. 研究结论只支持它实际证明的范围；不要把“可能”“据某人记述”改写成确定事实。

## 正式引用记录示例

```yaml
claim_id: "HIST-001"
class: "H2"
status: "supported"
source_tier: "S1"
bibliography: "作者／编者，题名，版本或出版信息"
library_relative_path: "史料/文件名.pdf"
locator: "第 00 页／卷次／条目"
upstream_source: null
critical: true
required_source_chains: 2
independent_source_chains: 2
reviewer: "历史研究员或具名审校 Agent"
reviewed_at: "YYYY-MM-DD"
reasoning_note: "该来源支持的范围、不能证明的部分和替代解释"
```

H1/H2 的发布记录必须具备上述适用字段。`unreviewed`、`rejected`、缺少定位、缺少审校者，或只引用 S4/S5 的记录均不得通过发布检查。`contested` 只能在争议本身被准确呈现、来源链完整且创始人书面接受风险时进入发布候选。

## 上下文控制

- 每轮先读目录、标题和命中片段，不直接读取整本长 PDF。
- 优先使用母库相对路径，避免在项目文档中重复超长绝对路径。
- 将来源摘录保持为最小必要长度；项目文档记录释义和定位，不复制整章材料。
- 一个任务结束后，把可靠结论固化到 `CLAIMS.md`，后续 Agent 先读台账再决定是否重开原文。
- 图片、扫描页和地图只在版式、物证、地理或图像细节确实影响判断时读取。
