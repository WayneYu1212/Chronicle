# 《佣书》（Chronicle）产品需求文档

文档版本：1.0

状态：产品主文档；十章 1.0 内容边界已由创始人批准
产品所有者：创始人兼执行制作人

## 1. 产品概要

《佣书》是一款以清初岭南为背景的单人历史互动叙事游戏。玩家不是帝王、将军或侦探，而是以整理文稿谋生的年轻佣书。玩家通过搜集、整理、查验、比对、拼接与编纂史料，寻找“真相”，记录历史，并承担史料被保存、误读、交易、隐藏或销毁的后果。

游戏当前时间固定为康熙九年（1670），距1650年庚寅之劫二十年。主角约二十三岁、出生于1647年，事件发生时约三岁；他知道“城破旧事”存在，但没有可靠亲历记忆。玩家调查的是事件细节、来源冲突与记忆如何被保存或改写，而不是第一次得知广州曾经城破。

产品承诺不是还原唯一真相，而是让玩家理解：历史记录由材料、记录者、权力、利益、缺失与传播共同形成。

## 2. 目标与非目标

### 2.1 产品目标

- 完成一部可独立发布的章节制个人游戏，而非只停留在概念 Demo。
- 让文献劳动成为核心玩法，而非对白之间的装饰性小游戏。
- 让玩家清楚区分原始材料、个人解释与传播历史。
- 让关键史料处置产生永久、可感知、跨章节延续的后果。
- 以克制而独特的纸本文献体验建立作品辨识度。
- 通过逐章完成、逐章验证控制个人项目范围。

### 2.2 当前非目标

- 多人、账号、云存档、实时服务或联网经济。
- 开放世界、战斗、角色养成或无限生成剧情。
- 以百科全书式说明取代玩家调查。
- 在当前里程碑提前实现第三章以后专属系统。
- 宣称争议历史问题存在唯一官方答案。

### 2.3 文档范围与版本策略

本文是持续更新的产品主文档。第 9 节定义当前可执行里程碑；它不等于《佣书》1.0 已经完成。1.0 固定为十章，按照“起—承—转—合”组织，最终以玩家完成关于“庚寅之劫”的历史书写为主线结局。每次批准新章节或产品级方向时更新版本、章节范围、验收标准与状态矩阵。

## 3. 目标玩家

### 核心玩家

- 喜欢历史、文献、博物馆、档案与物件叙事的玩家。
- 喜欢《奥伯拉丁的回归》式观察推断、但不要求高强度解谜的玩家。
- 喜欢节奏安静、文本克制、选择后果持久的独立叙事游戏玩家。

### 可访问性目标

- 不要求历史专业知识即可开始。
- 关键判断来自游戏内可观察证据，而非外部资料记忆。
- 支持鼠标、触摸与键盘可达的核心操作。
- 中文正文在桌面与移动设备上保持可读、可缩放和稳定字体回退。

## 4. 核心体验支柱

1. **搜集：**通过人物、地点、工作与交换获得材料，而非从菜单领取收藏品。
2. **整理：**依据体裁、来源和用途建立材料秩序，同时发现无法归类的异常。
3. **查验：**观察纸张、墨色、笔迹、折痕、印记、潮痕和纸背信息。
4. **比对：**把多份材料并置，判断同源、矛盾、转抄或缺失。
5. **拼接：**通过物理形态、正反面内容与语义恢复残缺材料。
6. **编纂：**记录解释、来源清晰度、可靠性和缺失证据，决定正文、附录或存疑。
7. **承担：**史料的出售、销毁、交还和著录改变后续证据、关系、金钱与风险。

## 5. 核心循环

```mermaid
flowchart LR
    Work["接受今日工作"] --> Act["执行文献劳动"]
    Act --> Discover["发现异常材料"]
    Discover --> Investigate["查验与比对"]
    Investigate --> Acquire["搜集新史料"]
    Acquire --> Compile["解释、编纂或处置"]
    Compile --> Consequence["关系、金钱、风险与证据变化"]
    Consequence --> Return["回到书坊／进入下一日"]
    Return --> Work
```

每一轮至少包含一个需要玩家观察或操作的职业行为。对白可以承载人物关系，但不能长期成为唯一推进方式。

## 6. 产品系统

### 6.1 章节与叙事状态

- 章节由有向剧情节点组成，支持对白、选择、标题和职业活动。
- 选择可改变信任、工钱、风险、线索、地点、手记和下一节点。
- 章节分支必须能够重汇合，但不能抹除已发生的永久后果。

### 6.2 文献活动

- 分类：选择或拖动文稿进入正确书匣；异常材料允许留在案上。
- 查验：切换正反面、移动灯光或聚焦证据点，记录观察。
- 比对：并置材料属性和文本，选择受证据支持的判断。
- 拼接：排列残片，以折痕、纸边、文字和纸背共同验证。
- 地图：发现、调查和选择地点；位置是证据与人物关系的入口。

### 6.3 史料编纂

每份史料应包含来源人物、发现地点、估计年代、载体、纸墨笔迹、标记、价值、政治风险、相关人物与事件、传递状态。

玩家可：

- 暂存待理；
- 收入正文或附录；
- 列入存疑卷；
- 出售；
- 销毁；
- 交还或转交。

收入长编时必须记录解释、来源清晰度、可靠性与缺失佐证。朱记数量有限，用来表达玩家当前关注点并影响后续提问。

- “据此可见”和“尚待旁证”默认由玩家自行填写，输入框分别以“这份材料说明了什么”和“还缺什么旁证”作直接提示。
- 每栏可独立选择“代拟”，填入项目预先审校的可编辑草案；代拟不得覆盖已有文字，不得自动落笔或替玩家保存判断。
- 代拟内容必须区分“材料如何记载”与“历史事实已经证实”，不得补足材料本身不能支持的身份、日期、动机或规模。

### 6.4 手记与档案

- 手记区分观察、判断、问题、待查与线索。
- 观察和判断不得被界面混为同一种“事实”。
- 档案随剧情解锁，为材料提供上下文，但不替玩家得出结论。

### 6.5 资源与关系

- 工钱影响现实生计和交易选择。
- 风险表达材料与行为带来的政治或社会暴露。
- 不同人物／群体的信任分别记录，避免单一善恶值。
- 数值变化必须能通过情境、选择反馈或后续可见结果被玩家理解。

### 6.6 存档

- 自动保存当前章节、节点、变量、线索、地点、手记、档案和编纂状态。
- 新版本必须尽量迁移旧存档；无法安全迁移时必须明确告知重置影响。
- 永久离手的原件不能因回退普通页面而恢复。

### 6.7 历史内容证据分级

所有可能被玩家理解为现实历史陈述的内容，在进入正式发布候选前必须登记到 `docs/research/CLAIMS.md`：

| 等级 | 含义 | 发布要求 |
|---|---|---|
| H1 可核查史实 | 年代、地点、事件、制度、器物或人物的可证事实 | 至少一个可追溯来源；重要或争议事实优先两条独立来源 |
| H2 来源支持推断 | 来源未直接陈述，但由材料支持的解释 | 记录来源、推理链、置信度与替代解释 |
| H3 设计推断 | 为玩法或叙事连接史实而作的合理设计判断 | 明确标记为设计推断，并由叙事总监与历史研究员批准 |
| H4 明确虚构 | 虚构人物、书坊、文稿、对白或合成情境 | 记录虚构目的及不得与已知史实冲突的边界 |

争议状态使用 `unreviewed`、`supported`、`contested`、`rejected`。没有来源记录的 H1/H2 内容不得通过历史发布审校；H3/H4 不得伪装成已证事实。

研究母库根路径与只读调用协议统一见 `docs/research/SOURCE_LIBRARY.md`。母库中的 AI 产出、摘要与旧版本仅用于发现线索；H1/H2 必须回到可追溯的原始文献或正式研究，并记录具体版本与页码。

口述来源必须记录事件日期、叙述日期和叙述者与事件的关系：`direct-witness`、`contemporary-retelling`、`intergenerational-retelling` 或 `later-memory`。游戏年代已固定为 1670；每次新增口述者都必须据其年龄与当年所在地核验亲历资格，不能把转述或后代记忆包装为直接见证。

## 7. 章节规划

### 第一章：第十三页

建立书坊、佣书职业与分类／查验／比对／拼接操作。结尾留下三个问题：残页由谁写成、老板为何认识、谁在寻找这些文稿。

### 第二章：双路线

《南海旧稿》与《书坊旧稿》让玩家第一次对原始史料做长期处置。路线必须改变编纂、工钱、风险、信任、证据和下一目的地。第二章不得完整解答第一章三个问题。

### 7.1 十章节奏

```mermaid
flowchart LR
    A["起 · 第1—2章<br/>进入书坊、发现残页、第一次处置史料"] -->
    B["承 · 第3—5章<br/>扩展地点、人物与来源网络"] -->
    C["转 · 第6—8章<br/>证词冲突、材料失去、记录者立场暴露"] -->
    D["合 · 第9—10章<br/>追索缺口、校勘来源、完成历史书写"]
```

| 段落 | 章节 | 叙事职责 | 玩家材料状态 |
|---|---:|---|---|
| 起 | 1—2 | 建立佣书劳动、核心疑问与第一次不可逆处置 | 从异常残页扩展到两条地方材料路线 |
| 承 | 3—5 | 扩大调查范围、人物关系与传播链；第三章双路线在肇庆汇合 | 开始同时拥有档案、抄本、私人书写与口述线索 |
| 转 | 6—8 | 让材料相互矛盾；揭示删改、沉默、误记和记录者自身立场 | 玩家必须面对证据缺失、原件离手和不可兼得的来源 |
| 合 | 9—10 | 追索最后的关键缺口，校勘不同来源，决定如何写入长编 | 来源多样性、可信度、缺失与玩家取舍共同塑造最终文本 |

具体章名、人物事件和单章玩法在对应里程碑中另行批准。本 PRD 固定叙事功能与结局，不提前虚构尚未研究和设计的细节。

### 7.2 主线结局

第十章的主要交付不是获得一份“真相道具”，而是完成一次可操作的历史书写。玩家必须把来自不同来源链的材料放入正文、附录、存疑或留白，并写明判断与缺失证据。

最终书写至少考虑：

- 官方或机构档案；
- 亲历者口述及其记忆偏差；
- 他人书写、转抄、译抄和后世整理；
- 物质证据与材料传播史；
- 玩家已经出售、销毁、交还或未能取得的材料。

来源“足够”不只按数量判断。进入结局需要满足最小来源多样性、关键事件覆盖和结构化著录要求；最终文本的可信度、矛盾、留白与风险随玩家的材料组合变化。游戏不提供唯一满分史书。

## 8. 视听与交互方向

- 关键词：安静、克制、纸、墨、木、暖光、呼吸、留白。
- 桌面以线装书双页为主，移动端收束为单页。
- 避免现代卡片堆叠、玻璃拟态、彩色 HUD、巨大悬浮按钮和夸张动效。
- 动画表现纸张移动、墨色显隐和光线变化；无弹跳、弹簧、无意义缩放或炫技转场。
- 声音以纸、木、雨、室内空间和劳动反馈为核心；允许安静，不以持续音乐填满体验。

## 9. 当前里程碑验收标准

当前状态说明：本节是目标验收，不代表各项已经满足。状态见 9.1。

- 玩家可从第一章连续进入第二章任一已开放路线并完成核心流程。
- 第一章四种劳动交互均可由鼠标／触摸完成，关键操作具备键盘可达路径。
- 玩家获得史料后能查看来源与物证，并完成结构化编纂判断。
- 至少一项原件处置不可逆，且其后果反映在编纂状态和至少两项变量／路径中。
- 两条第二章路线的数据引用、跳转、史料 ID 和结局节点通过自动校验。
- 存档可在刷新后恢复；旧版缺失字段可迁移到当前结构。
- 桌面与移动布局无阻断性溢出；中文字体、200% 缩放和减少动态效果模式可用。
- 类型检查、单元／数据测试、生产构建通过，并完成真实浏览器主流程检查。
- 未完成的真机、历史来源或可访问性检查必须明确列为发布阻断或已知风险。

### 9.2 最低发布闸门

- QA 总监拥有发布检查责任；只有创始人可以书面接受残余风险。
- 必测浏览器：当前稳定版桌面 Chromium、Firefox，以及真实 iPhone Safari；微信内置浏览器作为主要移动分发环境补充验证。
- Android Chrome 当前为尽力兼容、非阻断验证项；未测试时必须明确记录，不得宣称已经兼容。若后续受众或发行渠道改变，再由创始人提升为发布硬门槛。
- 必测布局：桌面双页、窄屏单页、触摸、键盘、200% 缩放、减少动态效果。
- 历史闸门：所有玩家可见 H1/H2 断言具有来源与审校状态；`unreviewed` 或 `rejected` 不得进入正式发布候选。
- 可访问性闸门：主流程无键盘阻断、焦点可见、关键反馈可被辅助技术感知、正文缩放不丢失内容。
- 测试或审校未完成时默认阻断；创始人可接受的只能是已知且书面记录的非核心残余风险。

## 10. 成功指标

### 体验研究信号

- 每个里程碑至少邀请 5 名未参与开发的目标玩家完成主流程并接受同一组访谈。
- 至少 4/5 能用自己的话区分“材料、解释、传播史”。
- 至少 4/5 能指出一个不是由对白直接告知的发现。
- 至少 4/5 能解释一项史料决定为何不可逆及其后果。
- “仍想追踪哪些材料或人物、为什么”作为方向性研究信号记录，不单独作为发布阻断。

### 质量指标

- 无阻断主流程的已知缺陷。
- 无孤立节点、失效跳转、未知史料 ID 或不可恢复存档错误。
- 正式完成声明附带自动化、浏览器和设备证据的明确范围。

## 11. 主要风险

| 风险 | 表现 | 应对 |
|---|---|---|
| 文本吞没玩法 | 长时间只点下一页 | 每个章节段落审查玩家动作与发现来源 |
| 历史被写成阴谋答案 | 单一反派或全知解释 | 维护来源、立场和争议标记；历史研究与独立审查 |
| 系统过度增长 | 为远期章节提前抽象 | 只实现当前及下一个确认里程碑共同需要的能力 |
| 永久选择不可信 | 后续无影响或原件复活 | 数据层约束、跨章测试和叙事 QA |
| 移动端阅读退化 | 字体、横排、触摸或页面溢出 | 真机回归作为发布证据，不以桌面构建替代 |
| 个人项目失控 | 同时扩张内容、工具和平台 | 逐章批准，L3/L4 由创始人决策 |

## 12. 产品决策权

创始人兼执行制作人拥有最终决策权。Studio Agent 可提出方案、阻止存在明确错误或风险的交付，但不能擅自改变产品核心、章节范围或作者立场。

## 13. 1.0 产品级完成定义

十章内容边界已经获批。1.0 必须同时满足：

- 十章主叙事完整实现“起—承—转—合”，不以“待后续章节”结束核心问题。
- 玩家至少一次完整经历搜集、整理、查验、比对、拼接、编纂与长期后果闭环。
- 主要人物、三项初始谜题与核心史料均获得有意的结论、开放结论或明确保留，而非遗漏。
- 玩家能够以档案、口述、他人书写等多种来源完成关于“庚寅之劫”的书写；最终文本显露来源、冲突、缺失和玩家选择。
- 所有批准章节、分支和永久状态通过自动化、浏览器、目标设备、历史审校和可访问性发布闸门。
- 商店页面／项目介绍、版本号、许可证、隐私说明、存档兼容说明和发布包准备完成。

尚待创始人决定：目标发布平台、发行语言与付费形态。这些决定影响发布计划，但不改变十章主线及其结局。
